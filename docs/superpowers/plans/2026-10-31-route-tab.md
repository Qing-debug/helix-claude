**Goal:** Hong starts, watches and stops the route walk from a "Route" tab in the main app (with the app's old screen
as the "Setup" tab), every run is saved with its frames and replayable with its reasons, and the key-test tools ask
"Is MapleStory closed? y/n" instead of listing programs.

**Architecture:** `walk.main`'s body moves into `RunSession` (`src/route/session.py`), which the walk CLI and the new
Route tab (`src/gui/route_tab.py`) both drive; the tab runs it on a daemon worker thread and drains a
`queue.SimpleQueue` of `RunEvent`s with `after`. The route view (`src/route_view/`) stops being a separate program:
`RouteViewWindow` packs into a Frame of the tab and `LiveController` follows the run folder as before, with the live
picture taken from the app's `SharedInfo`. The separate-program machinery (spawn, claim/ready, `win_focus`, the N1 tool)
and the capture thread's OpenCV window go.

**Tech Stack:** Python 3.14.0 venv · tkinter/ttk · returns · numpy · opencv-python · Pillow · import-linter ·
pytest. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-31-route-tab-design.md` (cited "spec 5.6" and so on). Decisions H55-H67 in
`docs/decisions.md` are Hong's and binding; H51-H54 still stand (spec section 2).

## Plan choices (local, reversible, inside the spec; each is a review item)

1. `RunSession` keeps every print of `walk.main` word for word (the walk tests pin them) and posts `RunEvent`s besides;
   in the app those prints go to the console. The countdown line `Focus the game window. Starting in {s:g} s. F12
   stops.` is printed once, just before the countdown steps, whatever `countdown_s` is (at 0 too, which is every CLI
   test: no step follows), as `walk.py:429` does today.
2. The countdown is `math.ceil(countdown_s)` steps; each posts `countdown` with `seconds_left` = steps left (n, n-1,
   ..., 1), sleeps `min(1.0, remaining)` with the `sleep` seam, then checks for a stop. `countdown_s = 0` (the CLI
   tests) is no step and no event; choice 1's line is still printed.
3. `ended` events with a code carry `text = f"{reason}/{source or ''}"` (the `stop.json` reason, or `"none"` when no
   `stop.json` was written, and the trigger source), so the tab can choose the 5.5 words without reading files;
   with `code=None` the text is the exception text (spec 5.6).
4. The tab builds the countdown line from `seconds_left` and the first count: `"Click the game now. Starting in " +
   " ... ".join(counts so far[-5:]) + (". F12 stops." if left == 1 else " ... F12 stops.")`: only the last five
   counts so far are shown, so a long countdown (up to 60, 5.3) still fits the status line; at 1 the line is
   "... Starting in 5 ... 4 ... 3 ... 2 ... 1. F12 stops." for any first count of 5 or more, the spec's line exactly
   at the default 5.
5. A `warning` event is appended to the status line after one space, in whatever state it is drained (Running, and
   also Stopping or Ended: the recorder can warn late), so the state's own text stays visible (plan review RA3 fyi).
6. F12 during the countdown (source `hotkey`, reason `cancelled`) shows "Ended: cancelled before the walk (you
   pressed F12)." (5.5 has no row for it).
7. (Removed 2026-11-01 by H68, Task RT-8c piece 3: no replay opens at the end, so no Ended text gets a folder name
   or " Replay is open."; the 5.5 texts stand alone and `endedText` loses `replay_open`. As RT-7 and RT-8b built it:)
   The "(<run folder name>). Replay is open." suffix of 5.2's Ended row is added to texts that start with `Ended:`
   when a replay actually opened at the end (`_onEnded` returns `True`, RT-8b: the live view ended into its replay,
   or the run folder loaded as one), not from a file check; a folder whose load failed, or a run with no view, gets
   no suffix (plan review RA3 I5). The 5.5 text's final full stop is dropped before it. A text that already names
   the folder (codes 6 and 7, "...; see <run folder>.", and the two "stopped unexpectedly" texts when they end "and
   <run folder>.") gets only " Replay is open." after its full stop, so the name is not shown twice. `Stopped:`,
   `Not started:` and `Could not start:` texts stand alone.
8. Readiness (the Not ready / Ready rows of 5.2) is re-evaluated on every 100 ms drain while idle (states
   `not_ready`, `ready`, `ended`) from the field validation and checks 1-3 of 5.4 (cheap, no matching). Check 3 here
   reads `gui.minimap_canvas is not None` and prints nothing: `MapleGUI._minimapReady()` prints
   `MINIMAP_NOT_FOUND_MESSAGE` into the Setup console when the minimap is missing (`gui.py:232-238`), which would add
   ten lines a second; only Start calls `_minimapReady()`. The refresh sets Start's enabled state on every drain, but
   writes the status line only when its result differs from its last write: it keeps the inputs of that write (the
   three field strings, `CSV_file`, the class, whether `minimap_canvas` exists) and its text, and writes when either
   changed. So a Start refusal (checks 4-6) or an Ended text stays until a field, the map, the class or the minimap
   state changes, instead of going back to "Ready. ..." within 100 ms (plan review RA3 I3). Start runs all six
   checks again.
9. GB means 2^30 bytes (what Explorer shows as GB): `START_FREE_BYTES = 2 * 2**30`, `RECORD_FLOOR_BYTES = 1 * 2**30`
   until RT-13 sets them.
10. The standalone `python -m src.route_view --follow <folder>` keeps `--replay` accepted and ignored (like `--record`
    in the walk, RTS95-D3), sets the root's title once at start (`Route view · <folder>`; outside any run, spec
    safety text), and loses `--ready`. That title call is why RT-4's test 10 title check covers only `window.py` and
    `follow.py` (the modules the app hosts during a run) and exempts `__main__.py`, whose docstring says it runs only
    on its own, outside any run.
11. `REPLAY_HINT` (`follow.py:39`) becomes "if the walk has ended or crashed, see the console; the replay opens when
    it ends". Amended 2026-11-01 (H68, H71; Task RT-8c piece 4): "if the walk has ended or crashed, see the console box
    on the Setup tab".
12. The live picture: `LiveController(..., live_frame=...)` reads a callable that returns the newest RGB frame from
    `SharedInfo` (read under the lock, lock released, then converted and scaled on the Tk thread); a new frame object
    counts as a change and is drawn with `RouteViewWindow.show(k, picture=...)`. While `live_frame` is given, the
    controller keeps the newest picture and passes it on every `show`, a tick where only the steps changed included
    (today that tick passes `background=self._background`, `follow.py:199`, a recorded file). The window keeps the
    last `picture` while `live` and its own re-shows `_redraw` and `_redraw_here` (`window.py:362-368`) pass it, so
    the picture never flips between live and recorded frames; `set_live(False)` drops it, so the replay draws the
    run's own frames. `shown_background` is `"live"` while a picture is shown. Without `live_frame` the controller
    behaves as built (frames from `frames/`).
13. Saved-run rows: `<local start time %Y-%m-%d %H:%M> <map file stem> <N laps> <size>`, columns separated by two
    spaces; start time from `session.json`'s `start_utc` converted to local time, map stem from its `map`, laps from
    the line count of `laps.jsonl`; `?` for what cannot be read; sorted by folder name, newest first. Size: `size ...`
    until summed, then `<n> MB` (rounded, 2^20 bytes) below 1000 MB and `<x.y> GB` (2^30 bytes) above: the same units
    as choice 9 and as Explorer.
14. The tab's seams for tests and the sim tool are constructor keywords of `RouteTab` (Contracts C5), one for each
    thing RT-7 to RT-10's tests fake: the session, the run root, free space, the new folder, the run's worker thread,
    the clock (`clock`, the 10 s close wait), the view and its controller (`make_view`, `make_live`), the replay loader
    (`load_run`) and the git head (`git_head`); tests pass fakes there and do not monkeypatch module names. `MapleGUI`
    takes `route_tab_factory` (default `RouteTab`).
15. Setting the recorder numbers from the measured rate (spec 5.11, section 11 step 12): refusal = max(2 GB, 4 h of
    recording) and floor = max(1 GB, 2 h of recording), each rounded up to 0.5 GB (the provisional numbers are 4 h and
    2 h at 0.5 GB/h). The tab's Recording line shows the measured rate to one decimal (`RECORD_GB_PER_HOUR`, C1).
    The floor need not grow with the rate: it only has to cover one disk check's worth of writing (600 frames, one
    minute at 10 fps, spec 5.6), which 1 GB does at any plausible rate; scaling it to 2 h is harmless (recording only
    stops earlier at a high rate) and keeps refusal minus floor at 2 h of recording or more at every rate, so it stays
    (plan review RA4 M10: a note, no change required).
16. `FakeStop.start` in `tests/route/test_walk_cli.py` gains `sigint: bool = True` (recorded as `self.sigint`): a
    test helper signature change, no patch and no assertion changes (spec 5.6 says the patches and assertions stay).
