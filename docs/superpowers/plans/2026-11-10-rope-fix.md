## Choices this plan makes (not Hong's words)

- **C1, precedence of H85's loose attach and the rope rule** (raised as `ROPE146-D1`, made provisionally): after 0.5 s still and off the map, H85's loose attach is tried first, as today. The rope rule runs when there is no line within 6 px (where H85 ended the run), **or** when a move planned from a loose attach left the read unchanged at that spot (the H85 limit "a still character within 6 px of a line, whose moves change nothing", which a rope 4-6 px under a platform hits). A loose attach whose move works is never second-guessed.
- **C2, how often**: at one spot the rope rule sends at most `rope_blink_tries` (2) blinks, if one is in reach, then one jump off, then ends the run `off_map`. A blink can be a no-op (live and in sim), hence two; Hong's order (blink, else jump off, `off_map` last) is kept.
- **C3, which way to jump off**: toward the leg target's x; right when it is level with the read.
- **C4, the `abilities` sim check** (raised as `ROPE146-D2`, made provisionally): it needs teleports down > 0, and drops > 0 only when the route graph has a DOWN edge that only a drop can make (none on FF2).
- **C5, the simulated rope grab**: a drop launched within `rope_grab_px` (2) of a rope's top grabs it (what DBG146 saw live). Because FF2 no longer drops, the simulator also has `NoiseConfig.rope_grab_p` (default 0, no draw at 0): a teleport down launched over a rope's top grabs it with that chance. That is a test device, not a live observation (DBG146 saw teleports down from node 7 work); `--real-ground` sets it to 0.2. The grab depth is drawn from `rope_grab_depth_px` (3, 9), so the three regimes are all exercised: 3 px (still placed by A2), 4-6 px (H85's loose attach, then C1's escalation) and 7-9 px (the rope rule at once, the live failure's 49).
- **C6, the new move's names**: `MoveKind.JUMP_OFF = "jump_off"`, `actions.jump_off`, `InputLayer.jump_off(direction, stimulus_ns)`; the plan name in the `ActionRecord` is `"jump_off"`; the route view shows "jump off left" and "Left+Alt".
- **C7, the DOWN edge's cost** follows D1: `route_graph._edge_cost` prices a DOWN edge at the teleport's cost when a teleport reaches, else the drop's (today it takes the cheaper of the two, which for a drop of under 12 px would price a move D1 never makes). - Produces: `planner.rope_move(rg, pos, gaps: tuple[float, float], target: Node, tries: int) -> Move | None`, pure, no rng. The order of moves at one spot: if a blink is in reach (`gap <= rg.reach_v`), `rope_blink_tries` blinks toward the closer in-reach line (`TELEPORT DOWN`, or `TELEPORT UP` when the line above is strictly closer; a tie goes down), then one `JUMP_OFF` toward `target`'s x (C3); with no blink in reach, the one `JUMP_OFF` only. `tries` indexes that order; past its end, `None`.

- Produces: `moves.execute` maps `JUMP_OFF` to `layer.jump_off(move.direction, stimulus_ns)`.
- Produces, in `walk_leg` (two new locals: `rope_tries = 0` and `futile_snap: tuple[int, int] | None = None`):
  1. Unchanged up to the 0.5 s wait: the rope rule runs only after `next_move` failed, `attach` failed and the read held for `standing_s`.
  2. Then, if `pos != futile_snap`: `attach_standing` as today; on success plan from the snap as today and remember `snap_from = pos` for this move.
  3. Else (no line within 6 px, or the spot is `futile_snap`): `gaps = platforms_around(rg, pos)`; a `Failure` ends the leg `OFF_MAP` with today's line (`the character is {failure}; ending the run`). Otherwise `move = rope_move(rg, pos, gaps, dst, rope_tries)`; `None` ends the leg `OFF_MAP` with the line `the character is on a rope at ({x}, {y}) and could not get off it; ending the run`; else `rope_tries += 1` and the move goes down the normal send path as `Decision(move, cost_to_go_s=<best if finite else 0.0>, toward=None)`, marked as a rope move.
  4. A rope move skips the progress update (step 6, `best` unchanged) but sets `last_progress = now`, so a rope never counts as progress toward the target and never trips the 10 s stall on its own. Everything else on the send path is shared: the stop check (7), the `planned`/`sent`/`settled` observer events, the `MoveEntry`, the link-down check, the settle.
  5. After a move planned from a snap settles: if the settled read equals `snap_from`, `futile_snap = snap_from` (C1).
  6. `rope_tries = 0` and `futile_snap = None` whenever `next_move` succeeds on a read (the `else: still.reset()` branch) or `attach` places the read; `futile_snap` also clears when a read differs from it.
