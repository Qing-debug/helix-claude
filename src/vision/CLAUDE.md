# src/vision: minimap capture

How it works is in the root CLAUDE.md ("Vision", "Threads and shared state"). `tests/vision/test_frame_wait.py` drives `frame_wait.py` and `cameraGrab` with a fake camera (Windows only); `tests/vision/test_minimap_follow.py` drives `minimap_follow.py` and, with `bettercam.create`, `vision_helper_lib.cameraGrab` (the whole-screen search), `vision._grab_stamped` (the minimap grabs), `vision._monotonic` (the clock of the 22 s re-find) and `time.sleep` patched on the `vision` module, the whole capture loop on synthetic screens built from the real corner templates (the loop tests skip where bettercam is missing); `tests/vision/test_frame_stamps.py` drives the stamps; two tests read `vision.py` as text (the last bullet under Traps).

## Traps

- Don't rename or restructure `vision.py` or `vision_helper_lib.py`: Feature C starts from Helix's rune work including its uncommitted changes to both files (`docs/superpowers/specs/2026-10-21-p1c-runes-design.md:28`), and a restructure here turns that port into a hand merge.
- `bettercam` is imported at module scope (vision.py:1), so importing `src.vision.vision` needs Windows and bettercam. `src/route` may import it only inside a function (`src/route/harness/record_minimap.py:179`); `tests/route/test_import_rules.py` and import-linter contract e enforce that.
- When the corner match fails, the loop calls `tracker.search_failed()` (one console line and `minimap_lost`, once per lost stretch; `isMatchedTemplateLocValid(..., verbose=False)` keeps its own reject lines quiet too) and goes straight back (`continue`) to another full-monitor grab and match, with no sleep (the grab itself still waits for a new image, next bullet). Inside the minimap loop, the grab's wait and `time.sleep(THREAD_SLEEP_DURATION_S)` (vision.py:98) pace it. `THREAD_SLEEP_DURATION_S` (vision.py:13) is 0.0: no fixed pause between pictures (H104, which amends H80's 20 ms floor; Hong's QB283 2b). `time.sleep(0)` on Windows is not a no-op: CPython's `pysleep` calls `Sleep(0)`, which gives the rest of the thread's time slice to any other thread that is ready to run and returns at once when none is (`Modules/timemodule.c`, the `MS_WINDOWS` branch, read in CPython's 3.14 branch on 2026-11-15). The value is pending Task 10B: the key-timing check (`tools/key_timing_check.py`, Hong-gated) decides whether the keys come late with the capture running flat out, and Task 10B may set a small pause here (then this bullet, H104 and the root Vision paragraph change).
- The follow check (VIS162-FIX; Hong, Q&A page vis162-1: "option 1, but drop the 5-second search if the tests allow it"). `minimap_follow.make_lock` keeps, from the whole-screen picture a search just matched on, the gray value of every pixel each corner's mask selects (the border line, never the inside) and the grab box (the four templates' union, a few pixels bigger than the minimap; the minimap is cropped out of it, so the published frame is the same pixels as before). `still_there` runs on every grab and fails when more than `MAX_CHANGED_FRACTION` (0.04: one pixel of a corner's 37 to 49) of any one corner's masked pixels differ by more than `PIXEL_TOLERANCE` (8 gray levels) from what they were at lock time. It compares pixels, not template scores, because the 0.95 score passes about 66% of positions with no minimap (VIS161-DBG), and a window in the border's own gray (228) still changes 3 to 8 masked pixels in every corner. Cost, measured: 54 us for `still_there` plus 21 us (210x150) to 58 us (800x500) for the gray conversion, under 0.5% of the 20 ms that H80's floor was when this was measured. A failed check publishes nothing and breaks to the whole-screen search; there is no periodic 5-second search, because no tested case slips past the check (moves of 1 to 60 px, resizes, minimap gone, dark, light and border-gray windows over all or one corner, a changing minimap inside, capture noise: `test_minimap_follow.py`). NOT proved on live pixels (no minimap was on the captured monitor when this was written): if the live border changes between frames, the check fails every grab, a search runs every grab and nothing is published; `tools`-free way to look: grab `lock.box` and count `still_there`. `LostTracker` is the one writer of `minimap_frame`, `minimap_frame_ns` and `minimap_lost` (all under `minimap_frame_lock`); `src/gui/CLAUDE.md` says what the windows do with the flag.
- Every grab waits inside Windows for a new desktop image (H77, Hong's QA116-1 answer): `cameraGrab` (vision_helper_lib.py, the whole-screen search) calls `frame_wait.grab_new_frame` (`src/vision/frame_wait.py`, `grab_new_frame_stamped` without the stamp) and the minimap grabs call `vision._grab_stamped` (next bullet), both over the same wait. That wait asks Windows' desktop duplication with `AcquireNextFrame(NEW_FRAME_TIMEOUT_MS = 100)` where bettercam's own `grab` passes 0, so it never spins on failed grabs: it returns at the next new image, or None after 100 ms on a screen where nothing changed, and `cameraGrab` asks again. An update that moved only the mouse pointer gives None. `cameraGrab` imports `frame_wait` inside the function because `frame_wait` loads bettercam and `src/route/harness/detection_check.py` imports `vision_helper_lib` without it (`test_41` in `tests/route/test_detection_check.py` checks bettercam stays out). Tests patch `frame_wait.grab_new_frame` and `frame_wait._query_texture` (the one call on a real COM pointer).
- Every picture the loop publishes carries a stamp (H104, Hong's QB283 2d): `frame_wait.grab_new_frame_stamped` (frame_wait.py:75) reads `time.perf_counter_ns()` (the seam `frame_wait._clock`, :55) on the line after `AcquireNextFrame` returns, the moment Windows handed the image over, before the copy, the crop and the colour conversion; it is not `LastPresentTime`. It is the clock of `RealClock.now_ns`, `InputLayer`'s stimulus and the recorder's `t_ns`. `vision._grab_stamped` (vision.py:21) is `cameraGrab`'s retry loop over it (it asks again at once on None, with no sleep) and the loop hands the stamp to `LostTracker.publish`; the whole-screen search keeps `vision.cameraGrab`, which drops the stamp, because it publishes nothing. The loop tests patch `vision._grab_stamped` (`test_minimap_follow.py`, `test_frame_stamps.py`, `tests/input/test_key_timing_check.py`) and `test_grab_stamped_retries_without_sleeping` runs the real one over a patched `frame_wait`.
- `LostTracker.publish` (`minimap_follow.py`) notifies: inside the same `with minimap_frame_lock` that stores the frame, its stamp and the cleared lost flag, it calls `SharedInfo.minimap_frame_new.notify_all()` (a `threading.Condition` on that lock, `src/main.py`; H104, Hong's QB283 2a), which wakes `wait_new` on the walker's thread (`src/route/position.py`, `src/route/CLAUDE.md`). `notify_all` needs the lock held (without it Python raises `RuntimeError: cannot notify on un-acquired lock`, run on the 3.14 venv), so the call stays inside the `with`. The condition shares `minimap_frame_lock`, so every `with minimap_frame_lock:` reader is unchanged.
- The minimap is searched for again every `MINIMAP_POSITION_RECALC_S` = 22.0 seconds (vision.py:11; H104, Hong's QB283 2c), counted on `vision._monotonic` (vision.py:12, `time.monotonic`, a seam so the tests move the clock and not the global one) from the moment the lock is made (`locked_at`, vision.py:80), and earlier when `still_there` fails, the region is invalid or the picture is black. The old count of 1000 pictures (`MINIMAP_POSITION_RECALC_INTERVAL`) is gone. Tests, all in `test_minimap_follow.py`: `test_minimap_is_re_found_after_22_seconds`, `test_the_period_restarts_after_every_re_find`, `test_the_period_restarts_when_the_minimap_comes_back_after_a_loss` and `test_fast_pictures_do_not_re_find_early`.
- `frame_wait.py` is a copy of bettercam 1.0.0's `BetterCam.grab`/`_grab` (`bettercam/bettercam.py:70-94`) and reads its private parts (`_duplicator`, `_device`, `_stagesurf`, `_processor`, `_on_output_change`, `_validate_region`). bettercam is pinned (`requirements.txt`, `bettercam==1.0.0`), and `test_bettercam_is_pinned_to_the_version_the_helper_copies` fails if the installed version changes or one of those names leaves bettercam's source. An upgrade means re-reading bettercam's grab path and updating the copy, not only the pin.
- `vision_helper_lib.py:3` imports `enum.Enum` unused; ruff's F401 is ignored for that file in `pyproject.toml` on purpose, so the file stays as Helix has it until the port.
- The capture loop opens no OpenCV window (H67, spec 5.12-5): the window's key wait became a 10 ms `FRAME_DELAY_MS` sleep (RT-11), which the grab's wait for a new image replaced (H77); the loop's sleep between pictures is `time.sleep(THREAD_SLEEP_DURATION_S)` at vision.py:98 (the 1 s `MINIMAP_DETECTION_RETRY_DELAY_S` wait after a black picture, vision.py:94, is the only other). Two tests in `tests/test_anti_cheat_names.py` read `vision.py` as text: the name scan (spec 5.12-4 and 5.12-5) fails if one of 5.12-5's three OpenCV window and key-wait names comes back, and `test_capture_loop_keeps_its_pause` fails if the pause line goes or `FRAME_DELAY_MS` comes back.
