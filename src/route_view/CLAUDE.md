# src/route_view: the route view

Spec: `docs/superpowers/specs/2026-10-27-route-view-design.md` (5.4 the window, 5.8 where the code lives) and `docs/superpowers/specs/2026-10-31-route-tab-design.md` (5.9, 5.13: the view is hosted, not a process of its own). Plan: `docs/superpowers/plans/2026-10-27-route-view.md`. A view that shows what the route walker planned and why, from a run folder: `RouteViewWindow` packs its widgets into a parent it is given, so it is hosted (by the Route tab's `view_frame`, `src/gui/CLAUDE.md`; by a root of its own in the standalone replay) and owns no window. It sends no key, needs no board and calls no Windows function. The walk no longer starts it (`--view` and the viewer spawn went in RT-2a); the two share only the files in the run folder, and the walk's side (`steps.jsonl` and the other files it writes) is in `src/route/CLAUDE.md`.

## Modules

- `model.py`: the pure view model, no Tk and no Windows call. `RunModel` (:290) is built from a `RunHeader` and `StepEvent`s from `src.route.step_log`; `load_folder` (:710) reads a whole run folder; `render_text` (:732) is the plain-text form the golden tests compare. Also `hop_route` (:218), `route_changed` (:223) and `read_frame_index` (:243). `SCALES` and `DEFAULT_SCALE = 4` (:68-69), the two warning lines `WARN_MAP` and `WARN_CODE` (:70-71), `FRAMES_DIR` and `FRAME_INDEX` (:72-73).
- `window.py`: `RouteViewWindow(parent, folder, model, *, live)` (:69), the view. Every widget is packed into `parent` (a `tk.Misc`; the images and variables are made with `master=parent`, and `after` is called on it); it makes no window and writes no window title. The title text (mode, folder, lap, leg, state, joined with ` · `) is `title_label`, the first widget packed, at the top of the view (`_update_title`, :429). `destroy()` (:192) stops playback and destroys the widgets it packed (the `parent` and whatever else is in it stay; a second call does nothing); a play tick already queued with `after` then does nothing. The window is built for one folder: the tab destroys it and builds a new one for the next run or replay. `show(k, *, background=None, picture=None)` (:210) draws step k; a `picture` (RGB, minimap size) wins over every file and shows as `shown_background == "live"`, and while the window is `live` it keeps the last `picture` for later `show`s without one and for `_redraw` and `_redraw_here`, until `set_live(False)` drops it (a window that is not live draws a `picture` once and keeps nothing; what feeds the picture is `LiveController`, see `follow.py` below); `set_live` (:267) hides the replay bar while live (`set_live(False)` puts it back; since RT-8c nothing calls it at the end of a run: the Route tab's kept view stays live, H69); the bar has no greyed-out state (`set_bar_enabled` went with H70, RT-8c: the Route tab keeps no view from Start); `set_status` (:284) and `add_warning` (:287) write the status line. `_draw` (:559) paints the picture; `NODE_R`, `ORANGE_R` and `RING_R` (:48-50), `PANEL_WIDTH_PX` (:58), `NO_STEPS` (:61). Draw order, bottom to top (`window.py:559-590`): the minimap picture, the faint recent moves, the route line, the nodes and their labels (`_draw_nodes`, :592), the target ring, the hop numbers, the aim cross, the character. So the route line and the recent moves lie under the node dots, which keep the dots and numbers readable. Only "the picture is the lowest item" is pinned by a test.
- `follow.py`: following a folder a walk is still writing. `Follower` (:59) reads the complete new lines of `steps.jsonl` and `frames/index.jsonl`; `LiveController` (:94) polls every `POLL_MS = 100` (:39) with `tick` (:132) and `update` (:138), says so after `SILENT_S = 10.0` (:40) with no new step (`SILENT_MODE`, :42, and `REPLAY_HINT`, :43), and at `end` stops following and leaves the window as last drawn: still live (no replay bar), its live picture kept, only the title's mode set to `ended: <reason>` from the `end` line's reason (`set_mode`; route tab H68, H69, RT-8c), and no call on the root (`_end`, :241). The owner learns of the end from `ended`: there is no callback. `stop()` (:127) ends the ticks: after it `tick` and `update` return at once, since a tick already queued with `after` can still fire. The live picture (route tab spec 5.8, plan choice 12): with `live_frame` given, each tick reads it (`_read_live_frame`, :223); a new array object makes a new `Image` (`Image.fromarray`), counts as a change, and is passed as `picture=` on every `show`, a tick where only the steps changed included; the same object or `None` keeps the picture made so far. The read runs after the poll has consumed the files, so it catches its own errors: one in the callable or in `Image.fromarray` goes to the status line and the console as `follow error: live frame: <type>: <message>`, the picture made so far stays, and the tick's polled lines are stored as normal (RT-5 review I1). The first model is preceded by one `show(0, picture=...)` so `set_model`'s own redraw reads no file. Without `live_frame` the frames come from `frames/` as before. The Route tab owns one per run and supplies `live_frame` and `report` (`src/gui/CLAUDE.md`): an error line (`follow error: ...`, once per distinct message) goes to `report`, which prints it on stdout by default (`_print_report`) and is the tab's console-box writer in the app (H71; RDO110-D3).
- `__main__.py`: the replay command line. `_parser` (:40), `main` (:51), `_git_head` (:28). `main` sets the root's title once, `Route view · <folder>` (:65), and builds the window in the root.

## Command line

`python -m src.route_view --follow <folder> [--replay]` (`_parser`, `__main__.py:40`). It only replays and runs only on its own, outside any run (route-tab plan choice 10).

- Any run folder opens as a replay on its last step: a `steps.jsonl` with or without an `end` line, or only `legs.jsonl` (an older walk). `--replay` is accepted and ignored. `--ready` is gone, so argparse refuses it with exit 2.
- Exit 2 also for a window that cannot be opened and for an unreadable folder (`error: ...` on stderr).
- On stdout: `window built in <s> s`.
- A `LiveController` that has not seen a step for 10 s says so in the status line and points to the console box on the Setup tab (`REPLAY_HINT`, `follow.py:42-43`, plan choice 11). Opening a replay on a folder still being written by a running walk is the thing to avoid (see "Traps").

## Run-folder files

- Reads: `steps.jsonl` (or the legs-only fallback, `legs.jsonl` and `session.json`), `map.csv`, `minimap.png`, `frames/index.jsonl` and the frames. The names are constants in `src/route/step_log.py:56-58`; the format is `step_log.py`'s (format V1).
- Shared with the walk: nothing but those files. The `view.log`, `view.claim` and `view.ready` files went with the viewer spawn (spec 5.13).

## Rules enforced by tests

- Two import-linter contracts in `pyproject.toml`: "route_view boundaries" (:77-85) forbids `src.gui`, `src.main`, `src.vision`, `src.rune_solver`, every `src.input` module but `protocol`, and the route modules that pull those in (`walker`, `walk`, `session`, `moves`, `runtime`, `sim`); "route_view is a leaf" (:87-93) means nothing in `route`, `controller`, `vision`, `input`, `classes` or `rune_solver` imports `src.route_view` (`src.gui` and `src.main` are not on that list: the Route tab, `src/gui/route_tab.py`, hosts the view, spec 5.9; the new contract at :96-101, "gui reaches input only through the run driver", is in `src/gui/CLAUDE.md`). What the package may import is spec 5.8. `tests/route_view/test_route_view_imports.py` pins the module lists in both contracts (:30), the gui-input contract (:41), that every `src.input` module but `protocol` is forbidden (:48) and that importing the model pulls in no Tk, `input_layer`, walker or GUI (:57).
- The view is built not to take focus (the design intent; the real-window check, H-1, has not run yet) and to make no style change to the window it is hosted in during a run (spec 5.13; see the traps). Test 10 pins it in four tests of `tests/route_view/test_view_window.py` (two checks, each with a planted-sample test). `test_10_the_viewer_never_takes_focus_or_rebuilds_the_wrapper_window` (:645) runs `focus_problems` (:611) over every `src/route_view/*.py`, `__main__.py` too: no `focus_force`, `focus_set`, `lift`, `tkraise`, `grab_set` or `-topmost`, no dialog module, and none of `resizable`, `overrideredirect`, `transient` or `attributes`, nor a `call("wm", ...)` (the names are `_FOCUS_ATTRS`, :605, and `_WRAPPER_CALLS`, :606; a planted sample at `test_10_the_walk_finds_a_planted_sample`, :654). `test_10_no_title_call_in_the_hosted_modules` (:666) runs `title_calls` (:636), which flags every `.title(...)` and `.wm_title(...)` call, over `window.py` and `follow.py` only, the two modules the app hosts during a run; `test_10_the_title_check_finds_a_planted_sample` (:673) is its planted sample. `__main__.py` is exempt from the title check: it sets the standalone replay's own title (plan choice 10), and it runs only on its own, never inside the app.

## Traps

- While the view is live, never call `focus_force`, `focus_set`, `lift`, `tkraise` or `grab_set`, and never open a dialog.
- Never call `wm resizable`, `overrideredirect`, `transient` or `attributes`, in any form. After the idle pass Tk rebuilds the wrapper window on these, and the app makes no style change to that window during a run (spec 5.13). The Tk source line cited by the review is `win/tkWinWm.c:5073-5076` (for `resizable`, Tk 8.6.15); it was not re-read for this note. Test 10 enforces the names.
- `window.py` and `follow.py` never set a window title (`.title(...)`, `.wm_title(...)`): the view lives inside the app's window and writes its title text to `title_label`. Only `__main__.py` sets a title, on its own root. Test 10's title check enforces it.
- Never open a replay while a walk runs. A replay window takes focus when clicked, and the board's keys go to whichever window has focus (root `CLAUDE.md`, Safety rules).
- The planned why line's route is `preview.path`; the panel's Route line is the hops' route (`model.py:14-15`). They can differ where the hops leave the path at an assumed landing (nine pairs on the FF2 map, none in the simulator runs).
- The why-line time is the local time of day, `HH:MM:SS.mmm`, from the header's `wall_ns` plus `t_ns - perf_ns` (`RunModel._stamp`, `model.py:410-414`; spec 5.10, H55 QB117). A header without `wall_ns` (sim runs, legs-only folders) keeps the elapsed time since the run's first event as `mm:ss.mmm` (`h:mm:ss.mmm` past an hour; `model.py:415-419`). `wall_ns` and `perf_ns` are declared at `step_log.py:96-97`.
- The scale buttons are in the replay bar, so they are hidden while the view is live; open with Hong (RV80-ADJ-D1).

## Tests and commands

`python -m pytest -q tests/route_view`. Test files: `test_route_view_imports`, `test_view_cli`, `test_view_follow`, `test_view_model` and `test_view_window`; flat helpers `view_runs.py` (builds run folders) and `view_tk.py` (a real, withdrawn Tk root that never runs a mainloop; `record_after` replaces `after` on a root or on a Frame). The window tests build the view in a Frame of such a root, as the Route tab will; `test_view_follow.py` and `test_view_cli.py` read the title text from `window.title_label`. A replay of a finished run: `python -m src.route_view --follow <folder>`.
