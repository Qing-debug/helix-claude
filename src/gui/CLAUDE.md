# src/gui: main window and map editor

camelCase package (root CLAUDE.md, "Naming"). `tests/controller/test_map_csv_characterization.py` calls `MapEditor._buildPreviewGraph` on a stand-in `self` to pin the preview order, and `tests/controller/test_map_load_errors.py` calls `MapleGUI._loadMapBrowse` the same way, with `filedialog` and `messagebox` patched, to pin the bad-map message box (decision H16). `tests/controller/test_gui_startup.py` is the one test that builds a real `MapleGUI` on a real, withdrawn Tk root (no mainloop; `after` is replaced by a recorder); it retries the Tk start a few times and skips if Tk still cannot start, because Tk now and then fails to read its own `init.tcl` on the dev PC. Its `make_gui` fixture hands `make(route_tab_factory=...)` to `MapleGUI` only when given, so a test of the Route tab can pass a fake and the rest get `MapleGUI`'s default. `tests/controller/test_gui_notebook.py` covers the Notebook below; its focus-record test sends Windows' `WM_SETFOCUS` and `WM_KILLFOCUS` to the Setup tab's console in the withdrawn root (in-process: nothing is shown, no key is sent, only the app's own window is addressed) and checks that `focus_get()` follows them, which the app-focus stop (spec 9) relies on.

## Traps

- The window is a `ttk.Notebook` (gui.py:168) with two tabs, "Setup" and "Route" (`setup_tab`, `route_tab_frame`, gui.py:169-173), 1120x1000 (gui.py:162). All of the old window is in the Setup tab: `_setupScrollableContainer` (gui.py:68) builds the scrolling column inside `setup_tab`; `scrollable_frame` is still the parent of every Setup widget and of the minimap Canvas; the eleven buttons and the class picker are attributes (`draw_blue_node_button` to `get_path_button`, `character_picker`) so the run lock can reach them. `isSetupTabShown()` (gui.py:150) says which tab is selected.
- The Route tab's object comes from `MapleGUI(..., *, route_tab_factory=None)`: the last step of `_setupGUI` calls `route_tab_factory(route_tab_frame, self)` and keeps the product in `route_tab` (gui.py:259-261). With no factory the tab is an empty frame and `route_tab` is None, so code that calls the route tab must work with None; anything that binds to the route tab (the focus bindings of spec 9) goes after that call.
- Closing the window: `_setupGUI` sets `WM_DELETE_WINDOW` to `_onClose` (gui.py:153, :163). With no route tab it destroys the root; with one it calls `route_tab.onAppClose(self.gui.destroy)` and the tab decides when the window goes.
- Preview order: `_buildPreviewGraph` (map_editor.py:837) inserts nodes in `map_format.ordered_local_ids` order (map_editor.py:853), the order `write_editor_nodes` (map_csv.py) writes, so the preview's edges match the runtime's after save→load. Change the order only in `ordered_local_ids`.
- The preview builds real `Node`s (map_editor.py:858), so every preview bumps the global `Node.node_id_counter` (`src/controller/CLAUDE.md`); editor loads don't.
- Startup does not wait for the game (decision H18). `_setupGUI` ends with a "Minimap not found yet" label (gui.py:255); `_updateCanvas` (gui.py:472) builds the minimap Canvas in its place on the first frame (`_createMinimapCanvas`, gui.py:455), like `MapEditor._waitForMinimapAndBuildCanvas` does. Until then `minimap_canvas` is None, so any new code that touches it or reads the character from the frame must start with `if not self._minimapReady(): return` (gui.py:263), as the four minimap buttons and `_openMapEditor` do (`_openMapEditor` does nothing else before the first frame: the editor's size checks on load and its node drawing are skipped while its canvas size is unknown, map_editor.py:753, :774, :1019, and nothing redraws the nodes once the canvas appears). Read `minimap_frame` under `minimap_frame_lock` into a local and release the lock before any Tk call or sleep (the old startup loop slept 10 s with the lock held and starved the vision thread).
- The buttons labelled "(delete or move to a separate tab on the GUI)" and "(delete after done testing)" (gui.py:224-241) are test leftovers: `connectCharacterNode` and `deleteNode` are wired with no node argument (controller.py:39-43). Don't build on them.
- The character picker uses `CharacterClass.__subclasses__()` (gui.py:197): direct subclasses only, so a new class must subclass `CharacterClass` directly.
- The GUI reaches past the `Controller` facade into `controller.agent` (gui.py:329, :333, :380, :418); the map editor does too (`buildPathGraphFor`, `characterClass`).
- The character is found by `_findCharacter` (gui.py:271) with route's `CharacterLocator` (decision H20), for "draw blue node on character", "draw orange node on character" and the dev get-path button. It builds the locator from `assets/chr/` on the first press and keeps it; on "miss", "ambiguous" or a bad frame it prints "Character not found on the minimap (<reason>)." in the console, returns None and the button does nothing more (no dot, `node_count` unchanged). Use it, after `_minimapReady()`, for any new button that needs the character's position. It matches outside `minimap_frame_lock`, like `_updateCanvas` draws. The old `getCharacterCoords` is gone; the controller cannot import `src.route` (import-linter contract c), which is why the lookup lives in the GUI. `gui.py` imports `src.route.character` only (no contract forbids it; contract d is the reverse direction): importing more of `src.route` here is a module-boundary change. Not tried on real game frames yet; its limits are in `src/route/character.py`.
- `tests/controller/test_gui_character_buttons.py` covers found, not-found and ambiguous for the three buttons on synthetic frames; it reuses the `make_gui` fixture of `test_gui_startup.py` by import (there is no `conftest.py`).
