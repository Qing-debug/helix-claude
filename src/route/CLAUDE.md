# src/route: route walking (Feature B)

Plan: `docs/superpowers/plans/2026-10-23-p1b-route-walking.md` (hard rules at the top, from line 43). The one-paragraph summary is in the root CLAUDE.md. The route view (`step_log.py`, `route_preview.py`, the walker's observer) was added by `docs/superpowers/plans/2026-10-27-route-view.md`; the viewer itself is the separate package `src/route_view/` (its own CLAUDE.md).

## The loop

- `RouteGraph.build(path_graph, params: MovementParams)` (route_graph.py:82) wraps the controller's `PathGraph` and infers terrain (`terrain.infer_terrain`, route_graph.py:18).
- `RouteWalker.walk_leg` (walker.py:191): `self._positions.read()` (:223) → `planner.next_move(rg, pos, dst, rng)` (:235; it anchors the position with `locate.attach`, planner.py:210) → `moves.execute(layer, move, stimulus_ns)` (:305) → settle → repeat from the measured position. When no plan comes back and `locate.attach` cannot place the position either, the rope rule (a read inside a marked rope's zone, `self._ropes.at(pos)`, :246) and then the still rule (see "Traps") decide between getting off the rope, waiting, a loose attach and ending the leg `off_map`. `run` cycles the rotation in laps and writes the leg and lap records.
- The step observer (route view): `RouteWalker(..., *, observer: StepObserver | None = None, log: Callable[[str], None] = _print_error, ropes: RopeZones = RopeZones.EMPTY)` (walker.py:159-172, `observer` stored :187; the protocol is :91; `log` and `ropes` are under "Traps", Frozen). `walk_leg` calls it at the V2 points: `leg` (:198), `stall` (:220), `read_failed` (:229), `no_plan` (:239), `reached` (:285), `planned` (:298), `sent` (:308), `settled` (:326) and `leg_end` (:346). Every site is `if self._observer is not None:` with the event, and any `clock.now_ns()` call, built inside it, so with `None` nothing else happens (the code-shape rule, spec 5.2). `_emit` (walker.py:420-427) reports an observer's first exception once, through the walker's `log`, and drops the observer for the rest of the run.

## Seams

- controller: `Node` and `PathGraph` (route_graph.py:15-16, terrain.py:14-15). `terrain.py:163` calls `PathGraph._isVerticalEdgeValid`, so that private name is part of the seam.
- input: `InputLayer` / `InputError` (moves.py:5-6, walker.py:52-53), `Key` (planner.py:17 and `sim/`). The simulator's `SimLink` (sim/link.py) stands in for `BleLink`.
- walk: `session.py` holds the walk's body (`RunSession`); `walk.py` is argument parsing plus the seams it passes at call time, so the walk tests' `setattr(walk, ...)` reach the run. `session` is the top layer of contract f (with `sim`) and is in the "route_view boundaries" list, so `src.route_view` never imports it.
- gui: `src/gui/gui.py` imports `CharacterLocator` (`from_files`, `locate`) from `character.py` (decision H20), so a change to those signatures or a move of `character.py` reaches the GUI. Contract d is the reverse direction (route may not import gui).
- vision: `harness/record_minimap.py:163` imports `src.vision.vision` inside `main`; `harness/detection_check.py` imports `src.vision.vision_helper_lib` (cv2/numpy/enum only, not bettercam) inside `crop_minimap` (:128); `pyproject.toml` contract e has an `ignore_imports` entry for each (:57-58). `position.py` reads the shared minimap frame; `character.py` is the character locator.
- position, the reference point (the off-graph fix, H85): `position.foot_from_dot` (`DOT_TO_FOOT_PX = 3`) moves the locator's dot centre 3 px down, to where map nodes sit, and both position sources apply it, `MinimapPositionSource` and `SimPositionSource` (`sim/link.py` imports it for that). - planner, from the route preview (RV1-D4 A, H53): `route_preview.py` imports eleven private helpers of `planner.py` (route_preview.py:38-52) and `_plan` (route_preview.py:134) repeats `next_move`'s rules (planner.py:200) statement for statement. The helpers, with their `planner.py` lines: `_edge_kind` (:44), `_is_at` (:48), `_on_slope_segment` (:60), `_starts` (:70), `_walk` (:88), `_run` (:93), `_walk_run_end` (:102), `_surface_ys` (:109), `_launch_x` (:137), `_offered` (:157), `_go_down` (:170). - step log: `step_log.py` is the route view's only input and the walk's and the simulator's output. Format V1: one JSON object per line (header keys `_HEADER_KEYS`, step_log.py:80-81; event table `FIELDS`, :62), one run per file (a second `run` line is a bad line, step_log.py:13), file names in `step_log.py:56-58`. The writer is `StepLog(*, log=_print_error)` (:466; a failed write is reported once through `log`, `_fail`, :632): a thread flushes, fsyncs and closes the file itself when it reaches the sentinel (`_drain`, :592), so `close` (:574) returns within its `join_s` and never touches a file a slow writer still holds.
