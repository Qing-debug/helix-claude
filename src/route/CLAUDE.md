# src/route: route walking (Feature B)

Plan: `docs/superpowers/plans/2026-10-23-p1b-route-walking.md` (hard rules at the top, from line 43). The one-paragraph summary is in the root CLAUDE.md. The route view (`step_log.py`, `route_preview.py`, the walker's observer) was added by `docs/superpowers/plans/2026-10-27-route-view.md`; the viewer itself is the separate package `src/route_view/` (its own CLAUDE.md).

## The loop

- `RouteGraph.build(path_graph, params: MovementParams)` (route_graph.py:82) wraps the controller's `PathGraph` and infers terrain (`terrain.infer_terrain`, route_graph.py:18).
- `RouteWalker.walk_leg` (walker.py:155): `self._positions.read()` (:184) → `planner.next_move(rg, pos, dst, rng)` (:195; it anchors the position with `locate.attach`, planner.py:193) → `moves.execute(layer, move, stimulus_ns)` (:224) → settle → repeat from the measured position. `run` cycles the rotation in laps and writes the leg and lap records.
- The step observer (route view): `RouteWalker(..., *, observer: StepObserver | None = None, log: Callable[[str], None] = _print_error)` (walker.py:136-137, `observer` stored :152; the protocol is :76; `log` is under "Traps", Frozen). `walk_leg` calls it at the V2 points: `leg` (:162), `stall` (:181), `read_failed` (:189), `no_plan` (:198), `reached` (:206), `planned` (:217), `sent` (:226), `settled` (:244) and `leg_end` (:264). Every site is `if self._observer is not None:` with the event, and any `clock.now_ns()` call, built inside it, so with `None` nothing else happens (the code-shape rule, spec 5.2). `_emit` (walker.py:338-346) reports an observer's first exception once, through the walker's `log`, and drops the observer for the rest of the run.

## Seams

- controller: `Node` and `PathGraph` (route_graph.py:15-16, terrain.py:14-15). `terrain.py:163` calls `PathGraph._isVerticalEdgeValid`, so that private name is part of the seam.
- input: `InputLayer` / `InputError` (moves.py:5-6, walker.py:46-47), `Key` (planner.py:17 and `sim/`). The simulator's `SimLink` (sim/link.py) stands in for `BleLink`.
- walk: `session.py` holds the walk's body (`RunSession`); `walk.py` is argument parsing plus the seams it passes at call time, so the walk tests' `setattr(walk, ...)` reach the run. `session` is the top layer of contract f (with `sim`) and is in the "route_view boundaries" list, so `src.route_view` never imports it.
- gui: `src/gui/gui.py` imports `CharacterLocator` (`from_files`, `locate`) from `character.py` (decision H20), so a change to those signatures or a move of `character.py` reaches the GUI. Contract d is the reverse direction (route may not import gui).
- vision: `harness/record_minimap.py:163` imports `src.vision.vision` inside `main`; `harness/detection_check.py` imports `src.vision.vision_helper_lib` (cv2/numpy/enum only, not bettercam) inside `crop_minimap` (:128); `pyproject.toml` contract e has an `ignore_imports` entry for each (:57-58). `position.py` reads the shared minimap frame; `character.py` is the character locator.
- planner, from the route preview (RV1-D4 A, H53): `route_preview.py` imports eleven private helpers of `planner.py` (route_preview.py:38-52) and `_plan` (route_preview.py:134) repeats `next_move`'s rules (planner.py:184) statement for statement. The helpers, with their `planner.py` lines: `_edge_kind` (:42), `_is_at` (:46), `_on_slope_segment` (:58), `_starts` (:68), `_walk` (:86), `_run` (:91), `_walk_run_end` (:100), `_surface_ys` (:107), `_launch_x` (:135), `_offered` (:155), `_go_down` (:168). A change to any of them, or to `next_move`, must keep the preview checks green: `tests/route/test_route_preview.py` (the hand-built table, S3 and S3b) and `tests/route/test_preview_sim.py` (slow; the preview against both 20-lap sim runs). `route_preview.py` never edits `planner.py`.
- step log: `step_log.py` is the route view's only input and the walk's and the simulator's output. Format V1: one JSON object per line (header keys `_HEADER_KEYS`, step_log.py:80-81; event table `FIELDS`, :62), one run per file (a second `run` line is a bad line, step_log.py:13), file names in `step_log.py:56-58`. The reader skips a torn last line and never raises (`read_run`, :356; `StepTail`, :320). The standard library and `returns` only, so it sits in the bottom layer of contract f (which is why it has its own `_print_error`, :460, instead of importing one). The writer is `StepLog(*, log=_print_error)` (:466; a failed write is reported once through `log`, `_fail`, :632): a thread flushes, fsyncs and closes the file itself when it reaches the sentinel (`_drain`, :592), so `close` (:574) returns within its `join_s` and never touches a file a slow writer still holds.

## Traps

- Frozen (the split-platform planner fix has landed, B14-inv-D1): `params`, `terrain`, `route_graph`, `locate`, `planner`, `moves`, `walker` and their tests (`test_params`, `test_terrain`, `test_route_graph`, `test_locate`, `test_planner`, `test_moves`, `test_walker_leg`, `test_walker_run`). Don't refactor or restyle them. There are two exceptions, both in `walker.py`: the step observer (the route view, RV1-D3 A, H53; the lines under "The loop") and the `log` keyword (RT-8c piece 4b, H71, ruling orch 111). The `log` keyword is exactly this and nothing wider: the module-level `_print_error` (walker.py:61, the old stderr print), `RouteWalker(..., *, observer=None, log=_print_error)` (:136-137) stored as `_log_line` (:153; not `_log`, which is the sink-result check, :332), and the two lines that used to `print` to stderr, the sink-failure line (`_log`, :336) and the observer-failure line (`_emit`, :345), which now call `self._log_line`. With no `log` given they print exactly as before (`test_7_the_guard_and_a_sink_failure_report_through_log` pins both cases), and `RunSession` passes its own (see the `RunSession` bullet). Everything else in the file stays frozen. `route_preview.py` calls the planner's private helpers and never edits it.
- `SimParams` (sim/world.py:117, what the simulated world does) and `MovementParams` (params.py:10, what the planner believes) share default values by copy. They are deliberately separate so the world can differ from the planner's belief: don't merge them.
- Stop guard (PB-D4; walker.py:57-58, `stop_now` at :286): after a stop, a guard thread (started at :294) sends `release_all` every 50 ms of wall time until `run` finishes. It is a safety mechanism (no key stays held): don't remove or slow it.
- Leg-log JSON keys are Feature D's contract: `tests/route/test_leg_log.py:26-29` pins `LEG_KEYS`, `MOVE_KEYS` and `LAP_KEYS`.
- `sim/run.py` `_write_offset_csv` (:159-178) is a third map-CSV reader and writer (`csv.DictReader` + `ast.literal_eval`, column name from `CSVParser().CSV_fields`); a map-format change must update it too.
- Every walk now writes `map.csv` (a byte copy of `--map`), `minimap.png` (the first frame it waited for) and `steps.jsonl` once the stop control has started (`session.py:493-513`; `_write_run_files`, :232). If that fails, the walk prints one line and walks on with no step log; its exit code does not change (RV3-D2 A with A1; `session.py:511-513`). `session.OUT_FILES` (`session.py:93`) has the three new names (`steps.jsonl`, `map.csv`, `minimap.png`), so a `--out` folder that holds any of them is refused.
- `RunSession` (`session.py`) runs on the Route tab's worker thread: it posts `RunEvent`s through `on_event` (the tab passes `queue.put`) and never touches Tk; every line it prints goes through `log` (default `_print_line`: stderr for an error line, else stdout, as walk did; the tab passes its console-box queue, route tab H71, RDO110-D3). The lines of the components it builds go through it too (RT-8c piece 4b, ruling orch 111): `_error_line` (`session.py:357`, its `log` with the error flag set) is passed as `log=` to `StepLog`, to `RouteWalker`, to the stop control and to `runtime.run_cleanup` (`session.py:484-487`, :623). The stop control comes from `make_stop(on_stop, log=...)`, so every `make_stop` factory takes `log` as a keyword (`MakeStop`, `session.py:115`; `runtime.StopControl` matches, and `walk.py`'s `_make_stop_control(on_stop, *, log)` hands it on, walk.py:65-66). Each of those takes the keyword with the old stderr print as its default (`runtime._print_error`, runtime.py:46, which also covers the hook thread's `remove()`; `walker._print_error`; `step_log._print_error`), so the CLI prints what it always did, and `harness/measure_moves.py`, which has its own `_make_stop_control` and calls `run_cleanup(steps)`, is untouched (its lines stay on stderr). The one line still printed to the terminal in an app run is the close's give-up line (`CLOSE_GAVE_UP_TEXT`, `src/gui/CLAUDE.md`). The tab passes `sigint=False`, because `signal.signal` fails off the main thread (`StopControl.start(sigint)`; the CLI passes `True`). `stop(source)` has two paths under one lock (`_stop_lock`, `session.py:332`): until `StopControl.start()` has succeeded it sets the cancel flag (first call only, with its `perf_counter_ns` stamp), which `run()` checks after each step; from then on it is `trigger(source)`. A flag set between the last check and `start()` triggers the stop control right after it (`session.py:497-500`). A stop before the walk exits 0 with `stop.json` reason `cancelled` (the flag's stamp when the flag was set). The stop control's `on_stop` is `_on_stop` (`:361`), not `walker.stop_now`: `stop_now` starts the stop guard, which ends only when `walker.run()` ends, and a run cancelled in the countdown never calls `walker.run()`. So `_on_stop` stops the walker only once `_hand_over` (`:376`) has handed it over, right before `walker.run()`; `_hand_over` calls `stop_now` itself if `on_stop` ran in between. The real stop control runs `on_stop` later than `trigger` (on its worker), so the countdown's end checks both `trigger_source` and `on_stop` (`LaterStop` in test_session.py fakes that). The recorder thread runs `_record_guarded` (`:267`), which turns any exception, a `Failure` or low disk space into one `warning` event; the walk goes on.
- A sim `--out` folder that already holds `steps.jsonl` makes `run_sim` fail and the CLI exit 2, before any file in it is touched (RV3-D3 A with A3; `sim/run.py:288-290`). The sim's `map.csv` is read inside `_load_shifted_agent`'s `with` block (`sim/run.py:186-190`, plan choice 7): a second write would draw from the world's random generator again and change the run. `observer` and `out_dir` together are a `Failure`.
- Runtime wiring (B19): `runtime.py` holds `StopControl` (F12 hook, Ctrl+C, `--minutes` timer) and the minimap capture helpers; `walk.py` is the supervised walk CLI (`python -m src.route.walk`; exit codes in its docstring, decisions B19-D1, B19-D2 and B19-D3; `--laps` below 1 is refused with exit 2 before anything starts, B19-D3, raised as B19-R M3). Both may import `src.vision` or Windows APIs only inside functions. Never run the CLI against a board without Hong's go; the live link check (`data/route/linkcheck/check.py`) is gitignored.
- Movement measurement tool (`harness/measure_moves.py`, B20): `python -m src.route.harness.measure_moves --supervised`. Its procedure (`_Session`) prompts on stdin between phases, settles each move by polling every 10 ms until one position holds for 0.5 s (B20-D2), appends to `measure.jsonl` and writes `summary.json`; exit codes and settle rules are in its docstring. A stop sets an event every prompt, move and settle poll checks and starts a `release_all` guard thread (as the walker's PB-D4 guard). `direction` is the `Key` name; no-op moves are left out of the summary (B20-D1). It shares `runtime.check_out`, `make_positions`, `SharedFrame` and `run_cleanup` with walk.py. Never run it without Hong (B21 step 3).
- Detection check (`harness/detection_check.py`, B18): `draft` and `check` read frames only through `load_frames` (:164), which returns `LoadedFrames(crops, uncroppable)` (:159). A full-screen frame that cannot be cropped is skipped, reported, drafted `null` and scored by `check` as nothing found (decision B18-D1). An unreadable PNG, unreadable corner images or no croppable frame at all exit 2. `draft` writes only inside `data/` and refuses to overwrite. `labels.json` is Hong's file: the tool never writes it, and an agent creates it only as a byte-for-byte copy of a `labels_draft.json` Hong has checked and approved (DET60, 2026-10-26), never with a mark of its own. Tests: `tests/route/test_detection_check.py` (all synthetic; test 41 is the slow `python -I` import proof).

## Commands and fixtures

Harness commands (repo root). The sim run, the detection check and the recorder send no keys (the recorder only reads the screen); the walk CLI and the measurement tool send keys and are never run without Hong's go:

- 1000-lap target run (plan task B14, spec B's offline targets; about 6 s; prints the counts and one `PASS` or `FAIL` line per check, exit 0 iff all pass): `python -m src.route.sim.run --laps 1000 --seed 1 --known-case 49,28:101,24 --known-case 101,24:105,42`. Its output at `1257222` is in spec B "As built". Re-run it after any change to the planner, the walker or the simulator. With `--out DIR` it also writes the leg log, `steps.jsonl` and `map.csv` (a new folder each time; see "Traps").
- Detection check (B18): `python -m src.route.harness.detection_check draft --frames DIR --out data/detection_check/<name>/labels_draft.json` finds the character by its dot's colour, writes the draft and its contact sheets (in `labels_draft_sheets/` beside it) and refuses to overwrite. Hong checks the sheets and saves `labels.json` (or approves the draft and has it copied unchanged). `python -m src.route.harness.detection_check check --frames DIR --labels data/detection_check/<name>/labels.json` scores the locator and exits 0 iff the hit rate is at least 0.995 with no wrong position. `DIR` is a B17 recording or a folder of full-screen frames. Last run: `data/recordings/ff2_2026-10-21` (character standing still), result in spec B "As built".
- Minimap recorder (B17; needs the game visible on the captured monitor): `python -m src.route.harness.record_minimap --out data/recordings/<name> [--seconds 120] [--fps 10]`. `--out` must be inside `data/`, and a folder that already holds a recording is refused (B17-D1). `python tools/recording_rate.py <that folder>` then prints MB and GB per hour for it (RT-13).
- Walk CLI (needs the board, the game and Hong; F12 stops): `python -m src.route.walk --map maps/fossil_foundry_2.csv --supervised [--laps N] [--minutes M] [--seed S] [--out DIR] [--record]`.
- Measurement tool (needs the board and the game, and runs in Hong's own console): `python -m src.route.harness.measure_moves --supervised [--out DIR] [--reps N]`.
- Replay of a finished run: `python -m src.route_view --follow <folder> [--replay]`. Never while a walk runs (root CLAUDE.md, Safety rules).
- Route-tab simulator (`tools/route_tab_sim.py`; no board, no game, no key: `SimLink` and a real-time clock under the real `RouteTab`, with no F12 hook installed): `python -u tools/route_tab_sim.py measure [--laps N]` walks the same run twice, once as the CLI does and once from the tab's Start, prints a table (median and p95 of the PC-side processing time from the position read to the send, the share of sends with no wait, the median reaction) and a verdict, and writes `data/route_tab_sim/<UTC stamp>/{cli,app}/` and `timing.json` (about 9 minutes at the default laps; exit 0 whatever the verdict, exit 2 on a refusal; `-u` because a killed run loses block-buffered output). An agent may run it on an idle PC (H15, H75). `python tools/route_tab_sim.py manual` opens the sim app for Hong's section-9 check and stays his. What the sim does not cover is the three lines `NOT_COVERED` in the tool holds and prints (`tools/route_tab_sim.py:69`); spec 12.2 spells them out.
