# src/route: route walking (Feature B)

Plan: `docs/superpowers/plans/2026-10-23-p1b-route-walking.md` (hard rules at the top, from line 43). The one-paragraph summary is in the root CLAUDE.md. The route view (`step_log.py`, `route_preview.py`, the walker's observer, `walk --view`) was added by `docs/superpowers/plans/2026-10-27-route-view.md`; the viewer itself is the separate package `src/route_view/` (its own CLAUDE.md).

## The loop

- `RouteGraph.build(path_graph, params: MovementParams)` (route_graph.py:82) wraps the controller's `PathGraph` and infers terrain (`terrain.infer_terrain`, route_graph.py:18).
- `RouteWalker.walk_leg` (walker.py:147): `self._positions.read()` (:176) → `planner.next_move(rg, pos, dst, rng)` (:187; it anchors the position with `locate.attach`, planner.py:193) → `moves.execute(layer, move, stimulus_ns)` (:216) → settle → repeat from the measured position. `run` cycles the rotation in laps and writes the leg and lap records.
- The step observer (route view): `RouteWalker(..., *, observer: StepObserver | None = None)` (walker.py:129-130, stored :145; the protocol is :70). `walk_leg` calls it at the V2 points: `leg` (:154), `stall` (:173), `read_failed` (:181), `no_plan` (:190), `reached` (:198), `planned` (:209), `sent` (:218), `settled` (:236) and `leg_end` (:256). Every site is `if self._observer is not None:` with the event, and any `clock.now_ns()` call, built inside it, so with `None` nothing else happens (the code-shape rule, spec 5.2). `_emit` (walker.py:330-338) prints an observer's first exception once and drops the observer for the rest of the run.

## Seams

- controller: `Node` and `PathGraph` (route_graph.py:15-16, terrain.py:14-15). `terrain.py:163` calls `PathGraph._isVerticalEdgeValid`, so that private name is part of the seam.
- input: `InputLayer` / `InputError` (moves.py:5-6, walker.py:45-46), `Key` (planner.py:17 and `sim/`). The simulator's `SimLink` (sim/link.py) stands in for `BleLink`.
- gui: `src/gui/gui.py` imports `CharacterLocator` (`from_files`, `locate`) from `character.py` (decision H20), so a change to those signatures or a move of `character.py` reaches the GUI. Contract d is the reverse direction (route may not import gui).
- vision: `harness/record_minimap.py:163` imports `src.vision.vision` inside `main`; `harness/detection_check.py` imports `src.vision.vision_helper_lib` (cv2/numpy/enum only, not bettercam) inside `crop_minimap` (:128); `pyproject.toml` contract e has an `ignore_imports` entry for each (:57-58). `position.py` reads the shared minimap frame; `character.py` is the character locator.
- planner, from the route preview (RV1-D4 A, H53): `route_preview.py` imports eleven private helpers of `planner.py` (route_preview.py:38-52) and `_plan` (route_preview.py:134) repeats `next_move`'s rules (planner.py:184) statement for statement. The helpers, with their `planner.py` lines: `_edge_kind` (:42), `_is_at` (:46), `_on_slope_segment` (:58), `_starts` (:68), `_walk` (:86), `_run` (:91), `_walk_run_end` (:100), `_surface_ys` (:107), `_launch_x` (:135), `_offered` (:155), `_go_down` (:168). A change to any of them, or to `next_move`, must keep the preview checks green: `tests/route/test_route_preview.py` (the hand-built table, S3 and S3b) and `tests/route/test_preview_sim.py` (slow; the preview against both 20-lap sim runs). `route_preview.py` never edits `planner.py`.
- step log: `step_log.py` is the route view's only input and the walk's and the simulator's output. Format V1: one JSON object per line (header keys `_HEADER_KEYS`, step_log.py:83-84; event table `FIELDS`, :77), one run per file (a second `run` line is a bad line, step_log.py:13), file names in `step_log.py:56-61`. The reader skips a torn last line and never raises (`read_run`, :359; `StepTail`, :323). The standard library and `returns` only, so it sits in the bottom layer of contract f. The writer is `StepLog` (:463): a thread flushes, fsyncs and closes the file itself when it reaches the sentinel (`_drain`, :588), so `close` (:570) returns within its `join_s` and never touches a file a slow writer still holds.

## Traps

- Frozen (the split-platform planner fix has landed, B14-inv-D1): `params`, `terrain`, `route_graph`, `locate`, `planner`, `moves`, `walker` and their tests (`test_params`, `test_terrain`, `test_route_graph`, `test_locate`, `test_planner`, `test_moves`, `test_walker_leg`, `test_walker_run`). Don't refactor or restyle them. The one exception is the step observer in `walker.py` (the route view, RV1-D3 A, H53; the lines under "The loop"); `route_preview.py` calls the planner's private helpers and never edits it.
- `SimParams` (sim/world.py:117, what the simulated world does) and `MovementParams` (params.py:10, what the planner believes) share default values by copy. They are deliberately separate so the world can differ from the planner's belief: don't merge them.
- Stop guard (PB-D4; walker.py:56-57, `stop_now` at :278): after a stop, a guard thread (started at :286) sends `release_all` every 50 ms of wall time until `run` finishes. It is a safety mechanism (no key stays held): don't remove or slow it.
- Leg-log JSON keys are Feature D's contract: `tests/route/test_leg_log.py:26-29` pins `LEG_KEYS`, `MOVE_KEYS` and `LAP_KEYS`.
- `sim/run.py` `_write_offset_csv` (:159-179) is a third map-CSV reader and writer (`csv.DictReader` + `ast.literal_eval`, column name from `CSVParser().CSV_fields`); a map-format change must update it too.
- Every walk now writes `map.csv` (a byte copy of `--map`), `minimap.png` (the first frame it waited for) and `steps.jsonl`, whether or not `--view` is given, once the stop control has started (`walk.py:394-408`; `_write_run_files`, :268). If that fails, the walk prints one line and walks on with no step log, no viewer and no `view.claim`; its exit code does not change (RV3-D2 A with A1; `walk.py:407-409`, the viewer start is guarded by `run_log is not None` at :423). `_OUT_FILES` (`walk.py:94-95`) has the six new names (`steps.jsonl`, `map.csv`, `minimap.png`, `view.log`, `view.claim`, `view.ready`), so a `--out` folder that holds any of them is refused.
- A sim `--out` folder that already holds `steps.jsonl` makes `run_sim` fail and the CLI exit 2, before any file in it is touched (RV3-D3 A with A3; `sim/run.py:288-290`). The sim's `map.csv` is read inside `_load_shifted_agent`'s `with` block (`sim/run.py:186-189`, plan choice 7): a second write would draw from the world's random generator again and change the run. `observer` and `out_dir` together are a `Failure`.
- Runtime wiring (B19): `runtime.py` holds `StopControl` (F12 hook, Ctrl+C, `--minutes` timer) and the minimap capture helpers; `walk.py` is the supervised walk CLI (`python -m src.route.walk`; exit codes in its docstring, decisions B19-D1, B19-D2 and B19-D3; `--laps` below 1 is refused with exit 2 before anything starts, B19-D3, raised as B19-R M3). Both may import `src.vision` or Windows APIs only inside functions. Never run the CLI against a board without Hong's go; the live link check (`data/route/linkcheck/check.py`) is gitignored.
- Movement measurement tool (`harness/measure_moves.py`, B20): `python -m src.route.harness.measure_moves --supervised`. Its procedure (`_Session`) prompts on stdin between phases, settles each move by polling every 10 ms until one position holds for 0.5 s (B20-D2), appends to `measure.jsonl` and writes `summary.json`; exit codes and settle rules are in its docstring. A stop sets an event every prompt, move and settle poll checks and starts a `release_all` guard thread (as the walker's PB-D4 guard). `direction` is the `Key` name; no-op moves are left out of the summary (B20-D1). It shares `runtime.check_out`, `make_positions`, `SharedFrame` and `run_cleanup` with walk.py. Never run it without Hong (B21 step 3).
- Detection check (`harness/detection_check.py`, B18): `draft` and `check` read frames only through `load_frames` (:164), which returns `LoadedFrames(crops, uncroppable)` (:159). A full-screen frame that cannot be cropped is skipped, reported, drafted `null` and scored by `check` as nothing found (decision B18-D1). An unreadable PNG, unreadable corner images or no croppable frame at all exit 2. `draft` writes only inside `data/` and refuses to overwrite. `labels.json` is Hong's file: the tool never writes it, and an agent creates it only as a byte-for-byte copy of a `labels_draft.json` Hong has checked and approved (DET60, 2026-10-26), never with a mark of its own. Tests: `tests/route/test_detection_check.py` (all synthetic; test 41 is the slow `python -I` import proof).
- N1 tool (`harness/view_check.py`, RV-10): see "Commands". Its MapleStory check, `_maple_check` (view_check.py:155), is patched by name in `tests/route/test_view_check.py` (:240): never move or rename it.

- Detection check (B18): `python -m src.route.harness.detection_check draft --frames DIR --out data/detection_check/<name>/labels_draft.json` finds the character by its dot's colour, writes the draft and its contact sheets (in `labels_draft_sheets/` beside it) and refuses to overwrite. - Measurement tool (needs the board and the game, and runs in Hong's own console): `python -m src.route.harness.measure_moves --supervised [--out DIR] [--reps N]`.
- N1 tool, the route view's no-key check (H-1; it sends no key and needs no board; module docstring `harness/view_check.py:1-47`):
  - `python -m src.route.harness.view_check run --dry-run [--out data/route_view/n1-<name>]` builds the simulator feed and reads it back (`_dry_run`, view_check.py:694): no viewer, no window, no Win32 call, exit 0. It still runs the MapleStory check first (`view_check.py:733-736`).
  - `python -m src.route.harness.view_check run [--out ...] [--laps 3]` starts the real viewer as a walk does, feeds it a simulator run line by line and reads the foreground window while someone clicks the view (four clicks, `CLICKS`, view_check.py:72). `after --out <that folder>` is run once `run` has exited and checks that the viewer outlived its parent. Both need a person to click, and `run` needs MapleStory closed.
  - Run `run` in a console window of its own, started by hand and used for nothing else. Its Ctrl+C check sends `CTRL_C_EVENT` to process group 0, which reaches every process on that console, and a process without a handler exits. So never run it through a pipe or `Tee-Object`, a `.bat` wrapper, an agent's shell tool or the console of a walk (the module docstring says the same, `view_check.py:15-21`; the tool does not test for it). An agent that runs H-1 opens a new console window for it and nobody else uses the PC (H15's idle rule).
  - Exit codes (`view_check.py:25-27`): 0 every check passed; 1 a check failed or was not done; 2 usage, an `--out` outside `data/` or already used, not Windows (without `--dry-run`), or standard input closed at one of its two questions (`n1.json` is still written and the checks not yet made are "not done", `run_checks` and `_run`, view_check.py:663-667 and :751-755); 3 MapleStory is running, or the process list cannot be read.
  - The Ctrl+C check has three failing outcomes (view_check.py:634-640). Only the detail "the viewer ended" (:640) means the spawn is wrong (the plan sends that back to spec 5.9 step 2). "The Ctrl+C was not delivered" (:637) and a detail that starts `GenerateConsoleCtrlEvent failed:` (:635; exit 1, ruled final) mean the check could not run: fix the launch (a fresh console window of its own) and run again, as for an exit 2 with standard input closed. A taskbar click that never comes is "not done", not a failure (:659-661).
  - H54 (docs/decisions.md): Hong let agents work with MapleStory open for tools that only open windows or move the mouse. This tool's own check has not been relaxed: at 75744de it still exits 3 with MapleStory running, `--dry-run` included, so H-1 still needs MapleStory closed until that check is changed.
- Replay of a finished run: `python -m src.route_view --follow <folder> [--replay]`. Never while a walk runs (root CLAUDE.md, Safety rules).
